# Rust

Правило: Rust только там, где измерено преимущество. UI, Activity, Service,
работа с Android API — Kotlin/Java.

## Кандидаты (по убыванию пользы)

| Модуль | Зачем | Как |
|---|---|---|
| Канонизация JSON + Ed25519 | проверка подписи без JVM-аллокаций, быстрый старт | crate `ed25519-dalek`, JNI |
| Разбор плагинов (zip, DEX-строки) | тяжёлый CPU на установке | `zip`, `dex-parser`, JNI |
| Поиск по журналу/источникам плагина | большие объёмы | `memchr`, JNI |
| Фильтрация списков | если профилирование покажет просадку | — |

## Требования к каждому переносу

1. Причина (профиль/замер).
2. JNI-обёртка с безопасными границами (без паник через FFI).
3. Тесты: unit в Rust + интеграционный вызов из Kotlin.
4. Замер до/после (время, память).
5. Fallback на Kotlin, если библиотека не загрузилась.

## Что НЕ переносим

Рендеринг, анимации, работу с сообщениями и сетью Telegram — выигрыша нет,
риск регрессий высокий.
