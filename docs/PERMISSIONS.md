# Разрешения плагинов

Модель взята из реального `PluginPermissions.java` exteraless (9 категорий).

| Ключ | Что разрешает | Риск |
|---|---|---|
| `ui` | элементы интерфейса | низкий |
| `messages.read` | чтение сообщений и апдейтов | высокий |
| `messages.send` | отправка/редактирование/удаление | высокий |
| `network` | сетевой доступ | средний |
| `files` | файлы вне своей папки | высокий |
| `intents` | перехват ссылок и intent | средний |
| `settings` | настройки приложения | средний |
| `hooks` | Java-хуки (полный контроль) | критический |
| `native` | загрузка нативных библиотек (полный контроль) | критический |

## Правила

1. `ui` выдаётся всегда, остальные — только с согласия пользователя.
2. Разрешение проверяется **при каждом** чувствительном вызове, не только
   при установке: единая точка `PluginPermissionManager.check(pluginId, perm)`.
3. Отказ → `SecurityException` в плагин + запись в журнал аудита.
4. Обновление плагина: новые разрешения **не** выдаются автоматически —
   показывается повторный запрос.
5. Импорт плагинов/настроек не восстанавливает опасные разрешения.
6. Обход через альтернативные API запрещён: все точки входа (сеть, файлы,
   intent, хуки, native) проходят через менеджер.

## Журнал

`PluginAuditJournal` (exteraless) расширяется полями: `pluginId`, `perm`,
`allowed`, `call`, `timestamp`. UI: поиск, фильтр по плагину/типу,
очистка, экспорт, детали записи.

## Защита от падений

Счётчик падений на плагин в пределах сессии и за запуск. Порог (по
умолчанию 3) → плагин отключается, в журнал пишется причина, остальные
плагины и клиент продолжают работу. Безопасный режим при старте
отключает все плагины, если предыдущий запуск завершился аварийно дважды.
